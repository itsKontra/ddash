# AdGuard Home's query log API: server-side search, filters and paging

Research for [#109](https://github.com/itsKontra/ddash/issues/109). Question: can the Device Page's Queries panel (by default the last 5 blocked queries for one client IP; expanded, search plus blocked/allowed and query-type filters over at most 50 rows) push its search and filters to AdGuard Home's `GET /control/querylog`, or must ddash do them?

**Target version.** The `adguard-api` Component's recorded testdata and tests are from AdGuard Home **v0.107.79** ([testdata/baseline/control/status.json L2](https://github.com/itsKontra/ddash/blob/1db64c5766ab09a6bbe3e5bf5607e2574c38f458/components/adguard-api/testdata/baseline/control/status.json#L2), [adguard_api_test.go L71](https://github.com/itsKontra/ddash/blob/1db64c5766ab09a6bbe3e5bf5607e2574c38f458/components/adguard-api/adguard_api_test.go#L71)). Tag `v0.107.79` is commit [`05ba17b`](https://github.com/AdguardTeam/AdGuardHome/tree/05ba17b282da1c4393d6a4ba4db0cf519194a362). All AdGuard Home links below point at that commit; `AGH` below is short for `https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362`.

## Answer in short

- **Can run in AdGuard:** the client restriction, blocked/allowed (via `reason`), and the "last N" limit. They AND together, and the default view (last 5 blocked for one IP) can be served in a single request.
- **Must run in ddash:** query type (no parameter exists), any time lower bound (only `older_than` exists), and free-text search *combined with* the client restriction. `search` is a single parameter and ddash already spends it on the client IP.
- **Paging:** cursor-based on `older_than`. `limit` counts *matching* rows, but a default request scans at most 50,000 log lines. With a sparse filter you can get fewer than `limit` rows (even zero) plus a cursor to continue. Sending `offset` (even `offset=0`) removes that scan cap.

## 1. Parameters that filter, and whether they combine

The spec lists `older_than`, `offset`, `limit`, `search`, `response_status` (deprecated) and `reason` ([AGH/openapi/openapi.yaml L193–L253](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/openapi/openapi.yaml#L193-L253)). The handler reads exactly three criteria, `search`, `response_status` and `reason`, in [AGH/internal/querylog/http.go L476–L510](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/http.go#L476-L510). Any other parameter is ignored.

- **There is no dedicated client parameter.** You filter by client through `search` (§2). The spec describes `search` as "Filter by domain name or client IP" ([openapi.yaml L218–L222](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/openapi/openapi.yaml#L218-L222)).
- **`search` takes one value.** It is read with `q.Get(name)`, so only the first `search=` counts ([http.go L356](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/http.go#L356)). You cannot send one exact client term and one domain substring term.
- **`response_status`** (deprecated) accepts one of `all`, `filtered`, `blocked`, `blocked_services`, `blocked_safebrowsing`, `blocked_parental`, `whitelisted`, `rewritten`, `safe_search`, `processed`. Anything else returns 400 ([AGH/internal/querylog/searchcriterion.go L35–L61](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/searchcriterion.go#L35-L61), [http.go L379–L382](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/http.go#L379-L382)). The spec's enum leaves out `blocked_services`, which the code accepts ([openapi.yaml L233–L242](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/openapi/openapi.yaml#L233-L242)). Note that `blocked` means only `FilteredBlackList` and `FilteredBlockedService`. Safe browsing and parental are separate values ([searchcriterion.go L263–L273](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/searchcriterion.go#L263-L273)).
- **`reason`** can be repeated and matches any of the given filtering reasons ([openapi.yaml L243–L253](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/openapi/openapi.yaml#L243-L253), [http.go L409–L427](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/http.go#L409-L427), [searchcriterion.go L189–L193](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/searchcriterion.go#L189-L193)). Allowed names: `NotFilteredNotFound`, `NotFilteredWhiteList`, `NotFilteredError`, `FilteredBlackList`, `FilteredSafeBrowsing`, `FilteredParental`, `FilteredInvalid`, `FilteredSafeSearch`, `FilteredBlockedService`, `Rewrite`, `RewriteEtcHosts`, `RewriteRule` ([AGH/internal/filtering/reason.go L63–L78](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/filtering/reason.go#L63-L78), [openapi.yaml L1487–L1502](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/openapi/openapi.yaml#L1487-L1502)). An unknown name returns 400.
  - `reason` is **new in v0.107.77**, which also deprecated `response_status` ([AGH/CHANGELOG.md L133–L137](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/CHANGELOG.md#L133-L137)). v0.107.76 reads only `search` and `response_status` ([v0.107.76 http.go L431–L442](https://github.com/AdguardTeam/AdGuardHome/blob/46eef4d2e2c7972893a23663496d21e00e862bd3/internal/querylog/http.go#L431-L442)), so an older AdGuard silently ignores `reason`.
  - `reason` and `response_status` together return 400 ([http.go L438–L441](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/http.go#L438-L441)).
  - **"Allowed" has no single value, but `reason` covers it.** Send the complement of the blocked reasons as a list, e.g. every name except `FilteredBlackList`, `FilteredSafeBrowsing`, `FilteredParental` and `FilteredBlockedService`. Whether `FilteredInvalid` and `FilteredSafeSearch` count as "allowed" is ddash's call. Today ddash treats them as not blocked ([querylog.go L26–L29](https://github.com/itsKontra/ddash/blob/1db64c5766ab09a6bbe3e5bf5607e2574c38f458/components/adguard-api/querylog.go#L26-L29)).
- **The criteria combine with AND.** Every parsed criterion is appended to one list ([http.go L494–L507](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/http.go#L494-L507)). An entry matches only if it passes `older_than` and every criterion ([AGH/internal/querylog/searchparams.go L66–L80](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/searchparams.go#L66-L80)). So `search="<ip>"` plus `reason=…` gives "this client's blocked queries" on the server.

## 2. What `search` matches

- **Fields:** the queried host (`QHost`), the client IP, the ClientID, and the client's name from AdGuard's client lookup ([searchcriterion.go L105–L133](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/searchcriterion.go#L105-L133), [L199–L214](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/searchcriterion.go#L199-L214)). It does **not** match the answer, the rule text, the upstream, the query type or the status.
- **Substring or exact:**
  - **Unquoted:** a case-insensitive substring match over any of those fields (`stringutil.ContainsFold`, [searchcriterion.go L120–L133](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/searchcriterion.go#L120-L133)). So the text `192` would also match every client whose IP contains `192`.
  - **Wrapped in double quotes:** the quotes are stripped and `strict` is set ([http.go L340–L347, L361](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/http.go#L340-L361)), giving a case-insensitive whole-value match on any one of those fields ([searchcriterion.go L105–L118](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/searchcriterion.go#L105-L118)).
- **IDN domains:** the term is lower-cased and also tried in punycode ([http.go L365–L378](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/http.go#L365-L378)). There is a TODO saying partial IDNs don't work.

## 3. Paging, `limit`, and caps

- **`older_than`:** an RFC 3339 nano timestamp. A bad value returns an error, and only entries strictly older than it match ([http.go L443–L449](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/http.go#L443-L449), [searchparams.go L68–L71](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/searchparams.go#L68-L71)). The response's `oldest` is the cursor for the next page ([openapi.yaml L2420–L2430](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/openapi/openapi.yaml#L2420-L2430)).
- **`limit`:** defaults to **500** when absent ([searchparams.go L31–L38](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/searchparams.go#L31-L38), [http.go L451–L454](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/http.go#L451-L454)). **There is no server-side upper cap**, and `limit=0` returns an empty list ([AGH/internal/querylog/search.go L106–L108](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/search.go#L106-L108)). ddash caps it at 500 itself (below).
- **`limit` counts matching rows.** Filters run while AdGuard reads, and reading stops once `offset+limit` matching entries are found ([search.go L218–L253](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/search.go#L218-L253)). The in-memory buffer and the file results are then merged and cut to `offset+limit` ([search.go L120–L127](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/search.go#L120-L127)). So a filtered request never returns more than `limit` rows.
- **The 50,000-line scan cap.** It can return *fewer*: by default one request scans at most 50,000 file entries, matching or not ([searchparams.go L25–L27, L36–L37](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/searchparams.go#L25-L37), [search.go L229](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/search.go#L229)). With a sparse filter, for example a quiet client's blocked queries, a page can hold fewer than `limit` rows, or **none**, while `oldest` is still set to the last scanned line's time ([search.go L238–L240, L283–L285](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/search.go#L238-L285)). You must keep paging. The in-memory buffer (default 1,000 entries, `querylog.size_memory`; [AGH/internal/home/config.go L421–L423, L536](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/home/config.go#L421-L423)) is always scanned in full ([search.go L53–L95](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/search.go#L53-L95)).
- **`offset`:** a row offset into the matching results, applied after sorting ([search.go L158–L164](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/search.go#L158-L164)). The spec recommends using either `offset` or `older_than`, not both ([openapi.yaml L205–L212](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/openapi/openapi.yaml#L205-L212)). **Any parsable `offset`, including `offset=0`, sets the scan cap to unlimited**, so AdGuard reads until it has `offset+limit` matches or reaches the end of the log ([http.go L456–L463](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/http.go#L456-L463)). That makes `limit` exact: you get `min(limit, total matches)` rows. The cost is a possible full scan of the log files (the current file plus `.1`, [search.go L197–L200](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/search.go#L197-L200)) on each call.
- **The `oldest` cursor:**
  - When the page has rows, `oldest` is the last returned row's time ([search.go L166–L169](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/search.go#L166-L169)), even on the last page. The end of the log therefore shows as one more call that returns no rows and an empty `oldest` (EOF clears it, [search.go L231–L234](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/search.go#L231-L234); `""` when zero, [AGH/internal/querylog/json.go L38–L44](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/json.go#L38-L44)).
  - Because `older_than` is strict, two entries with the same nanosecond timestamp at a page boundary would lose one.

## 4. Query type and time range

- **Query type (A, AAAA, HTTPS):** no filter exists. No such parameter is in the spec ([openapi.yaml L193–L253](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/openapi/openapi.yaml#L193-L253)), and the only criterion types are term, filtering status and reason ([searchcriterion.go L16–L33](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/searchcriterion.go#L16-L33)). The entry stores the type as `QT` ([AGH/internal/querylog/entry.go L23](https://github.com/AdguardTeam/AdGuardHome/blob/05ba17b282da1c4393d6a4ba4db0cf519194a362/internal/querylog/entry.go#L23)), but `search` never looks at it. **This filter must run in ddash.**
- **Time range:** only an upper bound, `older_than`. There is no `newer_than` or `since`. A lower bound has to be applied in ddash, by stopping once rows or `oldest` fall before it.

## 5. What ddash's `ListQueries` passes through today, and what it would need

Today ([components/adguard-api/querylog.go L31–L66](https://github.com/itsKontra/ddash/blob/1db64c5766ab09a6bbe3e5bf5607e2574c38f458/components/adguard-api/querylog.go#L31-L66), request message [adguard_api.proto L114–L125](https://github.com/itsKontra/ddash/blob/1db64c5766ab09a6bbe3e5bf5607e2574c38f458/components/adguard-api/adguard_api.proto#L114-L125)):

- `client` is parsed as an IP and sent as `search="<ip>"`, quoted so AdGuard matches it exactly ([L41–L42](https://github.com/itsKontra/ddash/blob/1db64c5766ab09a6bbe3e5bf5607e2574c38f458/components/adguard-api/querylog.go#L41-L42)). The exact match also hits a client *name* or domain equal to that string; harmless.
- `limit` defaults to 100 when it is 0 and is capped at 500 ([L21–L24, L36–L40](https://github.com/itsKontra/ddash/blob/1db64c5766ab09a6bbe3e5bf5607e2574c38f458/components/adguard-api/querylog.go#L21-L40)).
- `older_than` is passed through when set ([L43–L45](https://github.com/itsKontra/ddash/blob/1db64c5766ab09a6bbe3e5bf5607e2574c38f458/components/adguard-api/querylog.go#L43-L45)).
- `blocked_only` sends `reason=FilteredBlackList&reason=FilteredSafeBrowsing&reason=FilteredParental&reason=FilteredBlockedService` ([L26–L29, L46–L48](https://github.com/itsKontra/ddash/blob/1db64c5766ab09a6bbe3e5bf5607e2574c38f458/components/adguard-api/querylog.go#L26-L48)). It then drops non-blocked rows again in ddash for AdGuard older than v0.107.77, which ignores `reason` ([L57–L63](https://github.com/itsKontra/ddash/blob/1db64c5766ab09a6bbe3e5bf5607e2574c38f458/components/adguard-api/querylog.go#L57-L63)). On those versions a "blocked only" page can be shorter than `limit`.
- `offset` and `response_status` are not sent. The response carries rows plus `oldest`.
- The Queries panel asks for `{client: ip, limit: 100, blockedOnly}` ([plugins/network/src/queries.tsx L7, L40](https://github.com/itsKontra/ddash/blob/1db64c5766ab09a6bbe3e5bf5607e2574c38f458/plugins/network/src/queries.tsx#L40)) and does not page.

To support the new panel:

1. **Default view (last 5 blocked for one IP):** already fully server-side with today's RPC: `{client, limit: 5, blockedOnly: true}`. To make "5" exact on a quiet client, either send `offset=0`, which removes the 50k scan cap (see §3), or loop on `oldest` while the page is short and `oldest` is non-empty. Either change lives in the Component.
2. **Blocked / allowed:** add an "allowed only" mode, for example by replacing `bool blocked_only` with an enum `ALL | BLOCKED | ALLOWED`. It maps to the blocked or complementary `reason` list (§1). Still server-side and ANDed with the client.
3. **Free-text search:** since `search` is already spent on the client, there are two options:
   - (a) Keep the client exact on the server, then substring-match the text over domain (and anything else) in ddash.
   - (b) Send the text as `search` and check the client IP in ddash.
   Either way `limit` counts rows that are only filtered on one side, so ddash must page with `older_than` until it holds 50 matches or the log ends, with a page or scan budget. (a) is the natural fit: the client is the panel's fixed scope, and (b)'s unquoted `search` also matches other clients' IPs and names.
4. **Query type:** add e.g. `repeated string types` to the request and filter in the Component, also with the page-until-full loop.
5. **Time range (if wanted):** `older_than` as the upper bound. A lower bound is applied in ddash and stops the paging loop early.

Note for tests: ddash's fake AdGuard ([adguardfake.go L236–L291](https://github.com/itsKontra/ddash/blob/1db64c5766ab09a6bbe3e5bf5607e2574c38f458/components/adguard-api/adguardfake/adguardfake.go#L236-L291)) matches `search` and `reason` like the real one. It does **not** model the 50k scan cap, `offset`, `response_status`, or the real `oldest` behaviour: the fake returns `""` when the page is empty and never returns a "scan exhausted" cursor with zero rows. A paging loop needs a fake that can return a short or empty page with a cursor.
