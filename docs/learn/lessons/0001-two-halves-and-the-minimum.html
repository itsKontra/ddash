Two halves, one contract

A Plugin is a browser bundle. A Component is a Go process. The core starts the processes and the shell imports the bundles. By the end of this lesson you can name the smallest set of files and symbols each half needs, and what breaks when one is missing.

The picture

When the Operator installs a Plugin, two separate loaders do the work. Each has its own failure mode, so keep them apart in your head.

This split is ADR 0001. The ADR gives the reasons: crash isolation and no idle processes. Issue #19 has the full decision.

Half one: the Component process

A Component is a separate binary. The core runs it with exec.Command and talks to it through hashicorp/go-plugin over gRPC. The binary's whole main is one line:

func main() { sdk.Serve(ntfyapi.Definition()) }

components/ntfy-api/cmd/main.go:9

go-plugin starts the child, checks a magic cookie, and then hands both sides a gRPC connection. ddash's cookie is DDASH_COMPONENT (sdk/serve.go:18-22). The cookie stops someone running the binary by hand. It is not a security boundary: the SHA-256 SecureConfig is (core/runtime/subprocess.go:51).

Definition() wraps an sdk.Spec. The domain code you write implements two methods (sdk/component.go:43-53):

Start(ctx context.Context, env *sdk.Env, cfg C) error
Health(ctx context.Context) sdk.Health

The same value must also implement the gRPC server generated from your .proto. Embedding Unimplemented…Server is enough. sdk.Define checks this with reflection and panics if it doesn't hold (sdk/component.go:100-136). It also panics unless every RPC is unary and marked with exactly one of (ddash.getter) or (ddash.action).

These panics happen at Define time. A broken Component therefore fails in its own unit tests and in release.Build, before it can reach an Operator's machine.

Once the process is up, the core runs a fixed sequence in Runtime.launch (core/runtime/reconcile.go:166):

  1. Launch: go-plugin handshake, then Dispense("component") returns a *grpc.ClientConn.
  2. Describe: the Component reports its name, Release, requires and a FileDescriptorSet. The core refuses a wrong name or Release.
  3. Start: the core sends the stored config as protobuf bytes. An InvalidArgument error makes the Component Unconfigured. Any other error makes it Down.
  4. Health: polled every 30 s from then on.
Until Start succeeds, every API method answers FailedPrecondition "not configured" (sdk/instance.go:77-91). The host never sees a half-started Component.

Half two: the Plugin bundle

A Plugin has no backend code. It is a plugin.yaml plus one ESM file that Vite builds in library mode. React, react-router and @ddash/ui are left external, because the shell's import map supplies them. The shell loads it with a plain dynamic import:

export const importBundle = (url) => import(/* @vite-ignore */ url);

web/src/plugins.ts:8

The URL comes from ListInstalledPlugins (core/api.go:65). The module's default export must be a definePlugin({…}). Otherwise the Plugin shows as broken with the message its bundle has no definePlugin default export (web/src/plugins.ts:44). nav, pages and widgets are all optional.

definePlugin is an identity function (packages/plugin/src/define.ts:56). It exists only to type-check the object. The contract is the shape of the default export.

The seam that joins them: requires

A Plugin reaches Components only through the ones it lists in requires. That one list does three jobs:

  • Install: the core takes the transitive closure, dependencies first, and launches those Components (core/runtime/catalogue.go:194, installed.go:184-218).
  • Browser: the transport maps proto package ddash.<name-without-hyphens> to a required Component. Anything else is refused with PermissionDenied (packages/plugin/src/transport.ts:58).
  • Host: the router checks the same rule a second time, using the Ddash-Plugin header (core/router/router.go:185).
Watch out: the ddash.<name> package naming exists only as a convention in the TS transport. Nothing on the Go side enforces it. A Component whose proto package doesn't follow it installs and runs fine, but no Plugin can call it.

Check yourself

Answer from memory first. Scroll up only after you've committed to an answer.

1. A Component's RPC has neither (ddash.getter) nor (ddash.action). When does it fail?

2. Start returns InvalidArgument. Which state does the core give the Component?

3. A Plugin bundle exports definePlugin as a named export, not the default. What happens?

4. Plugin P requires Component A, and A requires B. Can P's UI call B directly?

Recall drill

Reveal

Ship: component.yaml, .proto (marked RPCs), Definition() via sdk.Define, a type with Start/Health and the embedded server, cmd/main.go calling sdk.Serve.
Lifecycle: Launch (handshake + Dispense) → Describe → Start → Health polling.
